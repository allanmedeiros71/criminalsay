<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer → Makefile | Developer invokes local build recipes; Makefile must not fetch or execute remote code |
| build → dist/ | Compiled binaries written to local filesystem; may contain embedded quote data paths |
| dist/ → VCS | Build artifacts must not enter git history |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | Makefile supply chain via curl\|wget\|bash | high | mitigate | Keep Makefile to local `go build` invocations only — no remote fetch, no `include` from URLs (D-01 scope, ASVS V10) |
| T-03-02 | Information Disclosure | Committed binary artifacts in git | medium | mitigate | `.gitignore` with `dist/` and `criminalsay` (D-15); verify with `git status` after `make all` (D-16) |
| T-03-03 | Tampering | CGO_ENABLED=1 cross-compile failure or unexpected native linking | medium | mitigate | `export CGO_ENABLED=0` at Makefile top (D-03); host default is 1 on linux/amd64 |
| T-03-04 | Denial of Service | make clean misses artifacts leaving stale binaries | low | mitigate | `clean` removes both `dist/` and root `criminalsay` per D-12 |
| T-03-05 | Elevation | World-writable dist/ permissions | low | accept | Default umask; local dev builds only — not a v1 deployment concern |

**Security summary:** Phase 3 Wave 1 adds no runtime attack surface. ASVS Level 1 satisfied by Makefile free of remote code execution and VCS hygiene preventing binary commits. One high-severity threat (T-03-01) mitigated by local-only recipes — block on any `curl`, `wget`, or remote `include` in Makefile.
</threat_model>
